## Runtime contract

Call `synthesize(text, private_output_dir, run=..., which=..., system=...,
config_dir=store.parent) -> Path`. The existing positional injection API is retained.
Omitting `config_dir` uses `TG_CTL_CONFIG_DIR`, otherwise `~/.config/tg-cli`.
No default acoustic voice or model is embedded in the library. An absent `voice.json`
refuses synthesis; no neural error invokes a host voice.

Canonical configuration is `<tg-cli config dir>/voice.json`, schema version 1:

```json
{
  "version": 1,
  "provider": "fish_audio",
  "model": "s2.1-pro-free",
  "voice_id": "REPLACE_WITH_CONFIRMED_VOICE_ID",
  "latency": "balanced",
  "format": "wav",
  "credential_source": {
    "type": "home_assistant",
    "path": "/absolute/path/to/homeassistant/.storage/core.config_entries",
    "entry_id": "REPLACE_WITH_VERIFIED_ENTRY_ID"
  }
}
```

This is a candidate, not an installed configuration. The orchestrator supplied verified
public metadata: Bracho A3, a retained selected voice ID, `s2.1-pro-free`, balanced latency.
It also supplied retained-selection evidence: `voice-design/models.json` named
`Брачо (A3)`, source `bracho_A_2.wav`, trained state, and retained Russian samples.
This worker did not reread those home files or independently validate the account/model.
The integrator must supply the verified original credential path and exact entry ID.
The resolver reads only `data.entries[]` matching `entry_id`, then `data.api_key`;
ambiguous, absent, malformed, or unsafe sources fail closed. No secret is copied into
voice.json, a report, another CLI config, or argv. An ordinary alternative is
`"credential_source": {"type":"env","name":"FISH_AUDIO_API_KEY"}`.
Config and credential-source files must be owned regular files, not symlinks or
writable by group/others; reads are limited to 1 MiB. Suggested config mode: 0600.
Unknown fields (including inline `api_key`) are rejected.

Provider/model/ID are required and pinned exactly. This adapter deliberately requests
PCM WAV so neural synthesis requires no ML packages or media decoder. `format: mp3`
is rejected; the standalone evaluator can decode MP3 with an existing ffmpeg.
Optional `base_url` must equal `https://api.fish.audio/v1/tts` exactly. HTTPS is direct,
with normal certificate verification, no proxy environment discovery and no redirects,
no retries and no model substitution. Requests use Bearer auth, the pinned `model`
header, and JSON `text`, `reference_id`, `format`, `latency`.
Transport runs in a child process with a hard 60 s timeout (killed and reaped),
covering blocked DNS and slow HTTP headers too. Auth/text go only through stdin;
stdout is limited by the worker to a safe timing header and validated WAV bytes.
Within the worker: 10 s socket operations, 60 s monotonic download budget, 8 MiB
maximum response, valid complete PCM WAV required. No error-body diagnostics escape.

Host engines require the explicit config `{"version":1,"provider":"host"}`.
That opt-in preserves macOS `say`/Linux `espeak-ng`/`espeak` engine selection,
Cyrillic voice handling and private text files; it is never automatic fallback.

The output directory must be owner-private (0700). Audio, text, and `tts.json` are
exclusive-created 0600 files; existing files/symlinks are not overwritten. Callers
own directory cleanup. Fish output is `say.wav`; host output keeps its WAV/AIFF
extension. A success requires an audio metrics report, not merely a nonempty file.

## Metrics and evaluation

`tts.json` contains version, provider, pinned model/voice_id/latency, optional host
engine, `time_to_first_audio_byte_ms`, `total_synth_ms`, and nested `audio` metrics.
No request text, credential value/source path, or provider error body is recorded.
First-byte latency measures the first HTTP audio-body byte after request start,
including the WAV header. It is independent of download completion; host first-byte
latency is null because the subprocess interface cannot observe it. Total synthesis
includes generation/download/validation and excludes technical signal evaluation.

`audio` includes decoded duration, sample rate/channels, real-time factor (total
synthesis duration / decoded duration), full-scale peak/RMS/dBFS, fraction of samples
with magnitude >=0.999, and leading/trailing/internal silence. Silence uses RMS
below -40 dBFS in 10 ms windows; internal gaps must span at least 100 ms. Fully
silent audio counts once as leading silence. Digital-silence dBFS is null.
Evaluation is bounded to 120 s and 64 MiB; WAV PCM widths 8/16/24/32 bits are supported.
For non-WAV files, existing ffmpeg is optional and local-only (`file,pipe` protocols).

`wer`/`cer` remain null with `asr_status: not_measured` until an independent ASR
hypothesis AND reference are supplied. Normalization: NFKC, casefold, ё→е,
non-alphanumeric→spaces, whitespace collapse; CER removes spaces. Both scores use
Levenshtein edit distance / reference length. Empty reference with insertions has
an undefined/null rate. No ASR model runs here. `naturalness_score` always remains
null pending a listener; signal metrics do not establish naturalness or identity.

Offline evaluator (no synthesis/provider call):

```sh
PYTHONPATH=features python3 -m telegram_client.tts_metrics /path/to/audio.wav \
  --reference 'Привет! 3d-house. Отчёт по Print Ops.' \
  --hypothesis 'independently transcribed text' --synth-ms 1234
```

It writes a JSON report to stdout; shell redirection may save it. `OFFLINE_CORPUS`
in the evaluator covers Russian introduction, 3d-house/Print Ops, numbers/dates,
acronyms, and short phrases. No corpus synthesis or bulk benchmark is implicit.
